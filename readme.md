# MoodFit — 기분·날씨·상황에 맞춘 AI 코디 추천

> "오늘 뭐 입지?"를 줄여 주는 서비스입니다. 오늘의 날씨와 기분, 일정(출근·데이트·면접 …)을 고르면
> **내 옷장에 실제로 있는 옷 중에서** 코디를 골라 주고, 왜 그 조합인지 설명합니다.

- 백엔드: **FastAPI** · SQLAlchemy(SQLite) · JWT 로그인 · Groq LLM · 기상청 단기예보 API
- 프론트엔드: HTML · CSS · JavaScript (빌드 도구 없이 FastAPI가 같이 서빙)
- 테스트: pytest 28개 (외부 API 없이 실행)

---

## 주요 기능

| 기능 | 내용 |
|------|------|
| 회원 | 회원가입·로그인, 비밀번호는 해시로만 저장, 로그인 토큰(JWT)으로 API 보호 |
| 내 프로필 | 성별·체형·피부톤·퍼스널 컬러·키·몸무게 → 추천 프롬프트에 반영 |
| 내 옷장 | 사진과 함께 옷 등록·수정·삭제. 사진 색상 자동 추출, 여러 장 한 번에 올린 뒤 카테고리만 눌러 정리 |
| 오늘의 날씨 | 현재 위치 또는 도시 이름으로 기상청 단기예보 조회 (기온·습도·강수확률·체감온도), 실패하면 직접 입력 |
| AI 코디 추천 | 규칙 점수로 후보를 먼저 고르고, LLM이 조합과 이유를 작성. 고른 옷은 사진 카드로 표시 |
| 착용 기록 | "이 코디로 결정"을 누르면 기록해, 다음 추천에서 최근 입은 옷이 덜 나오게 함 |

## 추천은 이렇게 동작합니다

LLM에게 옷장 전체를 그대로 넘기면 한여름에 패딩을 고르거나, 매번 같은 옷만 고르는 일이 생깁니다.
그래서 **규칙으로 먼저 점수를 매기고, LLM은 그 안에서 조합과 설명을 맡도록** 나눴습니다.

```
날씨·기분·상황 선택
  → 내 옷장의 옷마다 점수 계산 (app/services/scoring.py)
       날씨(계절) 30 · 상황 25 · 기분 20 · 최근 착용 10 · 색상 정보 5
  → 카테고리별 1순위는 ★, 계절이 크게 안 맞는 옷은 ⚠ 표시
  → 프로필·날씨와 함께 Groq LLM에 전달 (app/services/llm.py)
  → LLM 답의 [PICK] 블록에서 고른 옷 ID를 읽음
  → 서버가 "그 사용자의 옷인지, 상의 칸에 상의를 골랐는지" 다시 확인한 뒤 응답
```

- 기온으로 오늘의 계절을 정합니다. 23도 이상은 여름, 8도 이하는 겨울, 그 사이는 간절기예요.
- LLM이 존재하지 않는 ID나 남의 옷 ID를 쓰거나, 하의 칸에 상의를 넣으면 그 선택은 버립니다. 이 동작은 테스트로 확인합니다.
- 옷장이 비어 있으면 [PICK] 없이 일반적인 코디 조언을 줍니다.

## 프로토타입에서 바꾼 점

처음 버전은 HTML 파일 하나(약 1,500줄)로 만든 프로토타입이었습니다. 실제 서비스 구조로 옮기면서 다음 문제를 고쳤습니다.

| 문제 (이전) | 바꾼 방식 (지금) |
|-------------|------------------|
| Groq·기상청 API 키를 사용자가 브라우저에 입력하고, 브라우저가 외부 API를 직접 호출 → 키 노출 | 키는 서버 환경변수(.env)에만 두고, 브라우저는 우리 서버 API만 호출 |
| 회원 비밀번호를 브라우저 localStorage에 원문으로 저장 | PBKDF2-SHA256(사용자별 salt, 20만 회) 해시만 DB에 저장, 로그인은 JWT |
| 옷 사진을 localStorage에 저장 → 약 5MB에서 가득 참, 다른 기기에서 안 보임 | 브라우저에서 800px로 줄여 업로드, 서버 폴더에 저장하고 DB에는 파일 이름만 |
| 추천 결과에 나온 옷을 바로 "입은 옷"으로 기록 | "이 코디로 결정"을 눌렀을 때만 기록 |
| 체감온도를 `기온 − 풍속`으로 계산 | 기상청 겨울철 체감온도 공식 적용 (기온 10도 이하, 풍속 4.8km/h 이상일 때) |
| 지원이 끝난 모델(llama-3.3-70b-versatile)로 추천이 실패 | 모델 이름을 설정 한 곳(`GROQ_MODEL`)에서 관리, openai/gpt-oss-120b 사용 |
| 동작하지 않는 카카오·구글·애플 로그인 버튼 | 제거 (구현한 기능만 화면에 표시) |
| 없는 폴더(NestJS 모노레포)를 가리키는 package.json, docker-compose.yml | 제거. 초기 기획서는 `docs/planning.md`에 보관 |

## API

서버를 켜고 `http://127.0.0.1:8000/docs`에 들어가면 모든 API를 바로 호출해 볼 수 있습니다.

| 메서드 | 경로 | 설명 |
|--------|------|------|
| POST | `/api/auth/signup` | 회원가입 → 토큰 |
| POST | `/api/auth/login` | 로그인 → 토큰 |
| GET | `/api/me` | 내 정보 |
| PUT | `/api/me/profile` | 프로필 저장 |
| GET | `/api/wardrobe` | 내 옷 목록 |
| POST | `/api/wardrobe` | 옷 등록 (multipart, 사진 선택) |
| PATCH | `/api/wardrobe/{id}` | 옷 정보 수정 |
| DELETE | `/api/wardrobe/{id}` | 옷 삭제 (사진 파일도 삭제) |
| POST | `/api/wardrobe/wear` | 오늘 입은 옷 기록 |
| GET | `/api/weather?city=서울` 또는 `?lat=&lon=` | 지금 날씨 |
| POST | `/api/recommend` | AI 코디 추천 |

- 입력값은 Pydantic으로 검사합니다(정해진 기분·상황·카테고리만 허용, 비밀번호 8자 이상 등). 틀리면 422를 돌려줍니다.
- 남의 옷을 수정·삭제하려 하면 403이 아니라 404를 돌려줍니다. 다른 사람 옷의 존재 여부를 알 수 없게 하기 위해서예요.
- 로그인할 때 없는 이메일과 틀린 비밀번호에 같은 메시지를 줘서, 가입 여부를 알 수 없게 했습니다.
- 서버에 키가 없으면 503, 외부 API가 실패하면 502를 돌려줍니다. 화면은 이 상태 코드에 맞춰 안내합니다(날씨 → 직접 입력 등).
- 같은 격자·같은 발표 시각의 날씨는 30분 동안 서버 메모리에 저장해 기상청 호출을 줄입니다.

## 실행 방법

```bash
pip install -r requirements-dev.txt
copy .env.example .env        # Mac/Linux: cp .env.example .env  → 키 입력
python -m app.seed            # 데모 계정과 옷 12벌 만들기 (demo@moodfit.app / moodfit-demo)
uvicorn app.main:app --reload # http://127.0.0.1:8000
```

| 환경변수 | 설명 |
|----------|------|
| `GROQ_API_KEY` | [Groq](https://console.groq.com) API 키 — 없으면 추천만 503 |
| `KMA_API_KEY` | [공공데이터포털 기상청 단기예보](https://www.data.go.kr/data/15084084/openapi.do) 일반 인증키(**Decoding**) — 없으면 날씨는 직접 입력 |
| `SECRET_KEY` | 로그인 토큰 서명 키 — 배포할 때 반드시 긴 무작위 값으로 |
| `DATABASE_URL` | 기본 `sqlite:///moodfit.db`, PostgreSQL 주소로 바꿀 수 있음 |

## 테스트

```bash
python -m pytest
```

Groq와 기상청은 가짜 함수로 바꾸고, 테스트마다 빈 임시 DB를 씁니다.

- `test_auth.py`: 가입·로그인, 비밀번호가 원문으로 저장되지 않는지, 토큰 없는 요청 거절
- `test_wardrobe.py`: 등록·수정·삭제, 사진 형식·용량 제한, **다른 사용자의 옷에 접근할 수 없는지**
- `test_scoring.py`: 여름에 겨울 아우터가 1순위가 되지 않는지, 최근 입은 옷의 감점
- `test_recommend.py`: LLM이 남의 옷이나 맞지 않는 칸을 고르면 버리는지, LLM 오류가 503/502로 바뀌는지
- `test_weather.py`: 위경도 → 기상청 격자 변환(서울 60,127 / 부산 98,76), 발표 시각 계산, 체감온도

## 파일 구조

```
MoodFit/
├── app/
│   ├── main.py            # FastAPI 앱, 라우터 등록, 정적 파일 서빙
│   ├── config.py          # 환경변수 설정
│   ├── db.py, models.py   # SQLAlchemy 연결과 테이블 (users, clothing_items)
│   ├── schemas.py         # 요청·응답 형식과 입력 검증 (Pydantic)
│   ├── security.py        # 비밀번호 해시, JWT 발급·확인
│   ├── seed.py            # 데모 계정 만들기
│   ├── routers/           # auth, wardrobe, weather, recommend
│   └── services/          # scoring(규칙 점수), llm(프롬프트·Groq), weather(기상청)
├── static/                # index.html, style.css, app.js
├── tests/                 # pytest
└── docs/planning.md       # 초기 서비스 기획서
```

## 한계와 다음 단계

- 옷 사진을 보고 카테고리를 자동으로 분류하지는 않습니다. 사용자가 버튼으로 고르고, 색상만 사진의 평균 색으로 추정해요.
- 로그인 토큰은 브라우저 localStorage에 저장합니다. 서비스로 운영한다면 HttpOnly 쿠키로 바꾸는 게 더 안전합니다.
- 사진은 서버 폴더에 무작위 파일 이름으로 저장하고, 주소를 알면 볼 수 있습니다. 운영 환경에서는 S3 같은 저장소와 서명된 URL을 쓰는 게 맞습니다.
- 추천 품질을 숫자로 평가하지 않았습니다. "이 코디로 결정" 비율을 모아 규칙 가중치를 조정해 볼 계획입니다.
- 배포(Docker + Render 등)와 커뮤니티 기능은 아직 하지 않았습니다.
